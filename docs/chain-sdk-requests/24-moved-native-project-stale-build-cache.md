# Framework Request 24 — A moved native project must not keep a stale build cache

Source: the Lazify rewrite to Chain. `npm run build:mac`
(`chain build --target universal-apple-darwin`) fails on 2026-10-21 after
Chain moved `.chain/native` to `released/`. This blocks release builds.

**Not part of this request:**
- Changing how Tauri or Cargo word their own errors.
- The shared `chain dev` target dir.
- A verbose mode. Chain's condensed output already prints every line of the
  failure; nothing is lost.

## What happens

`prepareChainApp` (`packages/cli/src/nativeProject.ts`) renames a legacy
`.chain/native` to `released/` and, by design, keeps its `target/`. Cargo's
build-script outputs in that cache hold **absolute paths** into the old
location, and Cargo's fingerprints don't change when the target dir is
moved, so those outputs are reused as-is:

```
error: failed to run custom build command for `lazify v0.1.0 (/Users/…/lazify-chain/released)`
  …
  failed to read plugin permissions: failed to read file '/Users/…/lazify-chain/.chain/native/target/aarch64-apple-darwin/release/build/tauri-84f1e66d35818814/out/permissions/app/autogenerated/commands/app_hide.toml': No such file or directory (os error 2)
failed to build aarch64-apple-darwin binary: failed to build app
       Error failed to build aarch64-apple-darwin binary: failed to build app

✘ Build failed (exit 1).
  Error failed to build aarch64-apple-darwin binary: failed to build app
```

In Lazify's `released/target/`, 9 build-script `output` files under
`aarch64-apple-darwin/release` and 10 under `x86_64-apple-darwin/release`
still point at `.chain/native/target`. The host `release/` profile has since
been rebuilt and is clean, so plain `chain build` passes. Only the
cross-target builds the universal build depends on fail. Every app that was
migrated and keeps per-target caches will hit this.

## What Lazify needs

1. After Chain moves the native project, the next `chain build` (any
   `--target`) succeeds without the app deleting anything by hand. Whether
   Chain drops the old cache, keeps only path-independent parts, or cleans
   affected packages is Chain's decision. Note that `released/target/` also
   holds `chain-inspector.json`, which must survive.
2. Apps already migrated, like Lazify, recover too. The move has already
   happened, so a fix that only runs at move time doesn't reach them.
3. Smaller: the closing `✘ Build failed` summary should repeat the causal
   diagnostic (here the `error: failed to run custom build command …` line
   and its cause), not the last `Error` wrapper banner. `printFailureSummary`
   repeats `lastErrorLine`, which Tauri's wrapper overwrites last.

## Platforms

Observed on macOS, Apple Silicon, universal build. The move and Cargo's
absolute paths are platform-independent, so Windows and Linux cross-target
builds should behave the same; not verified.

## Suggested next step for chain-sdk

Add a fixture that builds a target, moves the native project the way
`prepareChainApp` does, and builds that target again. Also add a
`nativeOutput` fixture where a Cargo `error:` block is followed by a Tauri
`Error` banner, and check that the summary names the Cargo error.
