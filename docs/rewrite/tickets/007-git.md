working changes with line counts, file diffs, checkout, stage, unstage,

## What changed in the copy, and why

- `execFile` comes from `src/platform/exec.ts` (`process-runner`).
  `git-actions.ts` is otherwise byte-identical; `project-git-status.ts`
  differs only in joining `repoRoot` and the path with `/`.
- `agent-changes.ts`:
  - Untracked files are line-counted through `desktop.folders`
    (`readSmallText`, capped at the same 2 MB). A file that isn't valid
    UTF-8 counts 0 lines; Electron decoded it lossily and counted it unless
    it held a NUL byte.
  - The shadow store is `<appFolder("data")>/shadow-repos`, and its files
    are created through `desktop.folders`.
  - Electron named each run's folder by `process.pid` and, on launch and on
    quit, deleted folders whose process wasn't running. Chain has no
    process id, so a run is a random id kept in `sessionStorage`. That
    survives a page reload and is gone after a restart, which matches when
    Electron started afresh. Folders of other runs are deleted on first
    use. Two Lazify instances running at once would delete each other's
    folders; Chain apps are single-window today.
  - The folder name hash is the same SHA-1 prefix as Electron's, computed
    with Web Crypto.
  - `/dev/null` versus `NUL` follows `currentOs()`.

`@types/node` is a dev dependency, enabled only in `tsconfig.test.json`. The
app's `tsconfig.json` now says `"types": []`, so app code still can't use
Node's globals or modules by accident.
