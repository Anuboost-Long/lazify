# 001 — Prompt assembly into the shared core (Phase 1 / Proposed)

**Read this whole ticket before touching code.** Status: proposed. The
layout is accepted (A-3 in `../04-architecture-decisions.md`), and the
ticket waits on the `rewrite/integration` branch.

## Goal

Move the pure prompt-assembly code out of `src/main/prompts` into
`packages/core/prompts`. Both the Electron app and the Chain app can then
render identical prompts from one implementation. Electron behaviour stays
the same, and its output must be byte-for-byte identical.

## Status — 2026-10-09

Not started. No code has moved.

## Known coupling

`context-types/*.ts` imports `translation` from
`src/renderer/i18n/translation.ts`, which is generated by `npm run make:lang`.
The core must not depend on a renderer path. There are two options; decide
in review:
1. Pass the labels in as part of the input (the core stays i18n-free), or
2. Move the generated translation artifact somewhere both sides import from.
   This touches the `make:lang` script, so it is larger.

Option 1 is preferred if the rendered text does not change.

## Execution steps (small commits)

1. **Golden fixtures first.** Add `tests/core/prompt-assembly.golden.test.ts`.
   It calls today's `assemblePrompt` for every built-in preset, using
   representative context (global and project facts, rules, paths, commands),
   requirements, notes, priority and deadline. It stores the exact output
   strings as fixtures.
2. Create `packages/core/prompts/` and move the pure files with `git mv`.
3. Leave re-exports in `src/main/prompts/*` so no caller changes in this
   commit. Add the `@core/*` tsconfig path alias.
4. Resolve the translation coupling (see above).
5. Point callers at `@core/prompts` and remove the re-exports. Do this in a
   separate commit so it is easy to revert.
